服务端攻击客户端

分析：https://yschen20.github.io/2026/02/12/RMI%E5%9F%BA%E7%A1%80/#4-%E5%AE%A2%E6%88%B7%E7%AB%AF%E8%AF%B7%E6%B1%82%E6%9C%8D%E5%8A%A1%E7%AB%AF-%E5%AE%A2%E6%88%B7%E7%AB%AF

有两种情景：

  • 服务端返回 Object 对象
  • 远程加载对象

服务端返回Object对象

在RMI中，远程调用方法传递回来的不一定是一个基础数据类型（String、int），也有可能是对象，当服务端返回给客户端一个对象时，客户端就要对应的进行反序列化。所以我们需要伪造一个服务端，当客户端调用某个远程方法时，返回的参数是我们构造好的恶意对象。以CC1为例：

  • User接口，返回的是 Object 对象，服务端客户端都要有

  • 服务端实现 User 接口，返回CC1的恶意对象 Object 对象

  • 服务端将恶意对象绑定到注册中心

  • 客户端获取对象并调用getUser()方法，将反序列化服务端传来的恶意远程对象
